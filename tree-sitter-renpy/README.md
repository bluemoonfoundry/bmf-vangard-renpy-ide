# tree-sitter-renpy

Tree-sitter grammar for Ren'Py `.rpy` scripts, consumed by the app through
`web-tree-sitter` in `src/lib/tree-sitter/parseBlock.ts`.

## What is source and what is generated

| File | Kind |
|------|------|
| `grammar.js`, `src/scanner.c`, `queries/`, `test/corpus/` | **Source** — edit these |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/`, `bindings/` | Generated by `tree-sitter generate` |
| `renpy.wasm` | Build output, committed so the app runs without emscripten |
| `wasm-provenance.json` | SHA-256 of every build input and of `renpy.wasm` |

`renpy.wasm` is never edited or replaced by hand. The provenance manifest ties
it to the exact sources it was built from; `npm test` in the app fails if they
drift (`src/test/treeSitterGrammarProvenance.test.ts`). The same manifest
records the upstream package and hash of the vendored
`src/lib/tree-sitter/vendor/tree-sitter-python.wasm`
(`tree-sitter-python@0.23.6` from npm).

## Changing the grammar

Requirements: Node, plus **either** `emcc` (emscripten) on `PATH` **or** a
running Docker daemon. `tree-sitter-cli` (pinned at 0.24.7) compiles the wasm
inside the `emscripten/emsdk:3.1.64` image when `emcc` is not found, so
without one of the two the wasm step fails.

From the repo root:

```bash
npm run build:grammar   # generate parser.c, build renpy.wasm, update wasm-provenance.json
npm run check:grammar   # verify generated files + wasm match sources, run tree-sitter test
npm test                # app suite, includes the corpus via web-tree-sitter
```

Commit the regenerated `src/`, `renpy.wasm` and `wasm-provenance.json`
together with the `grammar.js`/`scanner.c` change.

The build is deterministic: the same sources, CLI version and emscripten image
produce a byte-identical `renpy.wasm`.

`tree-sitter test` (run by `check:grammar`) additionally needs a native C
compiler. The app's `npm test` runs the same corpus through `web-tree-sitter`
and needs neither a compiler nor Docker.

## Line endings

Every text file in this package is checked out with LF endings (see
`.gitattributes`). The corpus tests compare exact input, and a CRLF checkout
makes them fail.
