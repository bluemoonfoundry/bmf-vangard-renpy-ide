# nms4.3 Parser Corpus, Analysis Benchmarks and Cancellation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `r7pn` three safety nets: a broad tree-sitter-renpy corpus (with the grammar bugs it exposes fixed), recorded analysis benchmarks on small/medium/large projects, and worker cancellation so a stale analysis request never overwrites a newer one.

**Architecture:** A seeded in-memory project generator feeds a Vitest-run benchmark (separate config, not part of `npm test`). The analysis worker's request handler gains a per-request checkpoint (yield to the event loop, then "am I still the last request to arrive?") between phases and between symbol-index blocks; a superseded request throws `AnalysisCancelledError` internally, posts nothing and writes no cache. Grammar fixes land one bug per commit in `tree-sitter-renpy/`, each with corpus cases, a rebuilt `renpy.wasm`, and updated symbol-index consumers.

**Tech Stack:** TypeScript, Vitest 4 (jsdom + node), web-tree-sitter, tree-sitter-cli 0.24.7 + emscripten 3.1.64 (via Docker) for `renpy.wasm`, C external scanner.

**Spec:** `docs/superpowers/specs/2026-10-24-nms4.3-corpus-benchmarks-cancellation-design.md`

## Global Constraints

- Order: benchmarks (Tasks 1–2) → cancellation (Tasks 3–4) → corpus + grammar fixes (Tasks 5–13) → post-fix numbers (Task 14).
- Benchmarks are recorded, not enforced: never wired into `npm test`, `npm run gate` or CI.
- No cold-project-open timing. No renderer (`useRenpyAnalysis`) changes.
- "Newest request" = the last request to arrive at the handler; never compare request ids numerically.
- A cancelled request posts nothing (no progress, result or error) and writes neither `cachedSignatures`/`cachedResult` nor `ContributionCache.byBlockId`.
- Cancellation checks only between phases and between symbol-index blocks; no checks inside the regex phases.
- Fixtures: small = `DemoProject/game/*.rpy` as-is; medium ≈ 50 files / 20k lines; large ≈ 300 files / 150k lines; generated with a fixed seed, byte-identical across runs, not committed.
- Grammar bugs hit by new corpus cases are fixed in the grammar, one commit per bug, each closing its bd issue. Only exception: a bug needing a grammar *redesign* → file a new issue, leave that one case out with a comment naming the issue, tell the owner.
- After every grammar change: `npm run build:grammar` (Docker must be running), commit regenerated `tree-sitter-renpy/src/parser.c`, `src/node-types.json`, `src/grammar.json`, `renpy.wasm`, `wasm-provenance.json`; `npm run check:grammar` and `npm test` pass.
- Corpus expected trees are checked by hand against Ren'Py semantics before being committed, never pasted from parser output unreviewed.
- Repo conventions: `@/` imports, Git Bash, bd for tracking. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push without asking the owner.

## Review Focus

1. **CRLF files** (Windows-authored `.rpy`): the opaque `python_block`, the string-aware `expression`, and leading-blank-line handling must behave the same with `\r\n`. Test owned by Task 12 (plus a CRLF case in Task 6).
2. **Python bodies whose triple-quoted strings or open brackets continue onto less-indented lines**: Ren'Py joins those into one logical line, so the body must not end there. Test owned by Task 12.
3. **A burst of three requests**: only the third posts a result; the first two post nothing after the next one arrives. Test owned by Task 4.
4. **Hook remount (request ids restart at 1)**: a request with id 1 arriving after id 5 still completes and posts. Test owned by Task 4.
5. **Half-typed `python:` with nothing under it, followed by more code or EOF**: no `python_block`, no swallowed following statement, error stays local. Test owned by Task 12 (corpus) and Task 13.

### Task 4: Handler cancellation, plus the after-cancellation benchmark column

**Files:**
- Modify: `src/workers/analysisRequestHandler.ts`, `src/workers/renpyAnalysis.worker.ts` (docstring only), `docs/benchmarks/analysis-baseline.md`

**Interfaces:**
- Consumes: `AnalysisCancelledError`, `yieldToEventLoop`, `UpdateIndexDeps.checkpoint` (Task 3).
- Produces: `AnalysisHandlerDeps.updateIndex?: (cache: ContributionCache, blocks: IndexBlock[], deps?: { checkpoint?: () => Promise<void> }) => Promise<ProjectSymbolIndex>`. The default passes `checkpoint` through to `updateProjectIndex`. The handler signature is unchanged.

Behaviour:
- Each call takes `const token = ++arrivals` from a counter private to the handler. `checkpoint = async () => { await yieldToEventLoop(); if (token !== arrivals) throw new AnalysisCancelledError(); }`.
- Await the checkpoint before each phase: before "Parsing scripts", "Building route graph", "Analyzing translations", "Indexing symbols" and "Finalizing". Pass it into `updateIndex`.
- The index try/catch rethrows `AnalysisCancelledError`, with no `indexError` and no warning. The outer catch returns silently on `AnalysisCancelledError`. The fast path (unchanged signatures) is untouched.

- [ ] **Step 1: Write the failing tests.** Use a fake `updateIndex` with a gate per call: it awaits that call's gate (open by default for every call except A's), then `await deps?.checkpoint?.()`.

    - A posts no message after B arrived;
    - B's last message is a result;
    - a request with content Y (`id: 3`) is answered with exactly one message, a result (the fast path, which proves the cache holds B, not A);
    - a request with content X (`id: 4`) gets a full progress sequence.
  - `posts nothing at all for a request superseded before it starts` (burst; Review Focus 3): call A, B and C back to back without awaiting, then await all three. A and B post zero messages; C posts the full progress sequence and a result.
  - `still completes when ids restart after a remount` (Review Focus 4): complete id 5, then id 1 with new content. Id 1 posts a result.
  - The existing `posts progress phases …` test is unchanged and must still pass (uncontested behaviour).

### Task 12: `nms4.15`, opaque Python bodies

Decision:
- `python_statement` and `init_python_statement` bodies become one named external token, `python_block`, under field `body`. Its span runs from the first body line's first non-space character to the end of the last non-blank body line.
- The scanner ends the body before the first non-blank line whose indentation is ≤ the header line's, **unless** that line is inside an open triple-quoted string or an open bracket. Ren'Py's logical-line joining works the same way.

- `python:` with no deeper-indented line produces no `python_block` and no ERROR.
