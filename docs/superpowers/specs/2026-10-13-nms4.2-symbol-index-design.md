# Cross-File Symbol Index (tree-sitter)

**Status:** Draft (pending review)
**Date:** 2026-10-13
**Beads:** `bmf-vangard-renpy-ide-nms4.2` (parent epic `nms4`; blocked by grammar fixes `nms4.10`, `nms4.11`; unblocks `r7pn`)

## Problem

`src/lib/tree-sitter/symbolTable.ts` extracts *definitions* from a single block: labels, characters, screens, variables, images, menus, transforms and styles. It has three limitations that stop it backing project-level features:

- **No references.** Nothing records `jump`/`call` targets, `show`/`scene`/`hide` image uses, screen calls, say-statement speakers, or variable reads and writes.
- **No cross-file view.** Each block is an island, but most of what the app shows (the Project/Flow/Choices canvases, diagnostics, variable usage) relates names across files.
- **Not serializable.** Every symbol holds a live `SyntaxNode`. That is WASM-heap memory: it cannot cross the worker boundary and becomes invalid once its tree is freed.

`r7pn` (replace the regex analyzer), `jsp7` (editor intelligence) and `nms4.5` (definition/references) all need a project-wide index of definitions and references with stable identity and source ranges.

## Goals

- A project-wide index of **definitions and references** for labels, screens, menus, characters, variables (`define`/`default`/`$`/Python store assignments), images, transforms, styles and top-level Python functions and classes.
- **Stable symbol identity**: an ID that survives edits, moves and file re-ordering.
- **Source ranges** for every definition and reference (block, file, line/column, offsets).
- **Variable reads and writes inside Python** (`$` lines, `python:`/`init python:` blocks, conditions, screen and ATL expressions) and inside `[var]` string interpolation, with function and comprehension locals excluded.
- Plain serializable data, built in the analysis worker, with **incremental** rebuilds: only changed blocks are re-parsed.
- Unit tests resolve definitions and references **across multiple files** in a fixture project (the nms4.2 acceptance criterion).

## Non-Goals

- **Switching any consumer over.** Canvases, diagnostics, `VariableManager`, stats and the `RenpyAnalysisResult` adapter stay on the regex analyzer. That migration is `r7pn`.
- **Editor providers.** Definition, references, hover and completions are `nms4.5` and `jsp7`.
- **Degradation UI.** Showing parser or index failure to the user is `nms4.4`. This work only reports it in the worker response.
- **Stale-request cancellation and benchmarks.** These are `nms4.3`.
- **Incremental tree reuse** (`tree.edit` with long-lived trees). Caching happens per block contribution. Revisit only if `nms4.3` benchmarks show re-parsing changed blocks is too slow.
- **Grammar fixes.** Local/dotted labels (`nms4.10`) and `call`/`show`/`hide screen` (`nms4.11`) are fixed in their own PR first. This design assumes the corrected tree shapes.
- **Full Python semantics.** No type inference, imports, `global` declarations or attribute resolution beyond `store.`/`persistent.` normalization.

## Decisions (agreed during brainstorming)

| Decision | Choice |
|---|---|
| Sequencing | nms4.2 before r7pn; r7pn becomes a thin adapter over the index |
| Reference depth | Statement-level references **plus** Python identifier reads and writes |
| Architecture | Approach A: per-block contributions cached by content hash, plus a pure project-wide resolve pass |
| Symbol identity | `${kind}:${qualifiedName}`; a name defined twice is one symbol with two definitions |
| Variable use kinds | `refKind: 'read' \| 'write'` plus a separate `context` field (no Ren'Py-sounding names) |
| Grammar gaps | Filed as `nms4.10`/`nms4.11` and fixed first; nms4.2 depends on them |
| Worker output | New optional `symbolIndex` field on `RenpyAnalysisResult`, built alongside the regex analysis and unused by the UI until r7pn |

## Design

### 1. Data model (`src/types.ts`)

Everything is plain data: no `SyntaxNode`, no class instances, only `Map`s of plain objects, which survive `structuredClone`/`postMessage`.

```ts
export type SymbolKind =
  | 'label' | 'screen' | 'character' | 'variable' | 'image'
  | 'transform' | 'style' | 'python-function' | 'python-class';

/** `${kind}:${qualifiedName}` — e.g. 'label:start.sub', 'variable:persistent.seen_intro', 'image:eileen happy'. */
export type SymbolId = string;

export interface SourcePoint { line: number; column: number; offset: number } // line 1-based, column/offset 0-based

export interface SourceRange {
  blockId: string;
  filePath: string;
  start: SourcePoint;
  end: SourcePoint;
}

export type DefinitionKind =
  | 'label' | 'menu-label' | 'screen' | 'transform' | 'style' | 'image'
  | 'define' | 'default' | 'implicit' | 'python-assign' | 'def' | 'class';

export interface SymbolDefinition {
  symbolId: SymbolId;
  kind: SymbolKind;
  name: string;                 // qualified name, e.g. 'start.sub'
  defKind: DefinitionKind;
  range: SourceRange;           // whole statement
  nameRange: SourceRange;       // just the name, for navigation and rename
  enclosingLabel: SymbolId | null;
  detail?: string;              // parameter text, initial-value expression, style parent, ...
}

export type ReferenceKind =
  | 'jump' | 'call' | 'jump-expression' | 'call-expression'
  | 'show' | 'scene' | 'hide'
  | 'call-screen' | 'show-screen' | 'hide-screen' | 'use'
  | 'speaker'
  | 'read' | 'write';

export type ReferenceContext =
  | 'statement' | 'dollar' | 'python-block' | 'condition'
  | 'screen-expression' | 'atl-expression' | 'interpolation';

export interface SymbolReference {
  symbolId: SymbolId | null;    // null for dynamic jump/call expression targets
  kind: SymbolKind;
  name: string;
  refKind: ReferenceKind;
  context: ReferenceContext;
  range: SourceRange;
  enclosingLabel: SymbolId | null;
}

export interface MenuChoiceInfo { text: string; condition: string | null; range: SourceRange }
export interface MenuInfo {
  range: SourceRange;
  labelId: SymbolId | null;     // named menu (`menu foo:`) defines label foo
  enclosingLabel: SymbolId | null;
  choices: MenuChoiceInfo[];
}

export interface PythonBlockInfo {
  range: SourceRange;
  kind: 'python' | 'init-python';
  priority: number | null;      // `init 5 python:` → 5
}

export interface BlockContribution {
  blockId: string;
  filePath: string;
  contentHash: number;          // djb2, same function the worker already uses
  hasError: boolean;            // root node hasError
  definitions: SymbolDefinition[];
  references: SymbolReference[];
  menus: MenuInfo[];
  pythonBlocks: PythonBlockInfo[];
}

export interface IndexedSymbol {
  id: SymbolId;
  kind: SymbolKind;
  name: string;
  definitions: SymbolDefinition[];
  references: SymbolReference[];
}

export interface ProjectSymbolIndex {
  symbols: Map<SymbolId, IndexedSymbol>;
  unresolved: SymbolReference[];
  duplicates: SymbolId[];
  contributions: Map<string, BlockContribution>; // by blockId
}
```

Identity rules:

- **Labels** are keyed by their fully qualified name. A local label `.sub` under global label `start` is `label:start.sub`, and so is the dotted form `start.sub`. A named menu (`menu choose:`) defines `label:choose` with `defKind: 'menu-label'`.
- **Characters** get their own kind even though Ren'Py treats them as variables, because the app treats them differently. `define e = Character(...)` defines `character:e`. Any other `define`/`default` defines `variable:<name>`.
- **Images** are keyed by their full name (`image:eileen happy`). Image references resolve by **tag** (the first word); see Section 3.
- **Variables** reached through `store.x` normalize to `variable:x`. `persistent.x` keeps its prefix: `variable:persistent.x`.
- **Duplicates.** One symbol collects every definition of the same ID. Only labels and screens report duplicates, because Ren'Py errors on those. Images, transforms, styles and variables are legally redefined.

### 2. Per-block contribution (`src/lib/tree-sitter/blockContribution.ts`)

```ts
export async function buildBlockContribution(
  block: { id: string; filePath: string; content: string },
): Promise<BlockContribution>;
```

It calls `parseBlock`, walks the Ren'Py tree and every Python injection tree, copies everything into plain data, and calls `disposeParsedBlock` in a `finally`. No `SyntaxNode` escapes. It supersedes `symbolTable.ts` as the source for project-level data; `symbolTable.ts` and `ParsedBlock.symbolTable` stay as they are for now. Folding them into the contribution builder is follow-up work once r7pn lands.

**Ren'Py tree walk.** A single pass that tracks the enclosing global label, which local labels are qualified against:

| Construct | Produces |
|---|---|
| `label x:`, `label .x:`, `label g.x:` | definition `label:<qualified>` |
| `menu x:` | definition `label:x` (`menu-label`) + `MenuInfo` |
| `menu:` | `MenuInfo` only |
| `screen`, `transform`, `style`, `image` | definitions of that kind (`style` detail = parent) |
| `define`/`default x = …` | definition `variable:x` or `character:x` (when the value starts with `Character(`) |
| `jump x` / `call x` (incl. `.x`, `g.x`) | reference `label:<qualified>`, `refKind` `jump`/`call` |
| `jump expression …` / `call expression …` | reference with `symbolId: null`, `refKind` `jump-expression`/`call-expression` |
| `call x from y` | reference to `x`; definition of `label:y` (Ren'Py creates the return label) |
| `show`/`scene`/`hide <image …>` | reference `image:<full name>`, `refKind` `show`/`scene`/`hide` |
| `call`/`show`/`hide screen x` | reference `screen:x` (tree shapes per nms4.11) |
| screen-language `use x` | reference `screen:x`, `refKind` `use` |
| `e "text"` | reference `character:e`, `refKind` `speaker` (skipped for narration and string-expression speakers) |
| `[name]` / `[name.attr]` / `[name!t]` in say and menu-choice strings | `read` of `variable:name`, `context: 'interpolation'` |
| `python:` / `init [N] python:` | `PythonBlockInfo` |

Every symbol named in the nms4.2 issue is covered: labels, screens, menus, variables, calls/jumps, images, transforms and Python blocks.

**Python walk.** Over each injection from `parseBlock`. Python node offsets are relative to the dedented span text, so they are mapped back to `.rpy` offsets: line `0` maps to the injection's start plus the same column, and line `n > 0` maps to the original line with the dedent column added back. A CRLF test covers this mapping.

- `context` comes from the injection kind and its parent statement: `dollar` for `$`, `python-block` for `python:`/`init python:`, `condition` for `if`/`elif`/`while`/menu-choice conditions, `screen-expression` and `atl-expression` for the rest.
- **Writes**: assignment and augmented-assignment targets, including tuple/list unpacking targets, `for` targets at store level, and `store.x = …`.
- **Reads**: every other identifier in load position.
- **Locals**: names bound inside a `def`, `lambda` or comprehension (parameters, assignments in the body, loop targets) are skipped within that scope. Everything at the top level of a `$` line or a `python:` body is store-level.
- **Attributes**: `store.x` → `variable:x`; `persistent.x` → `variable:persistent.x`; any other `a.b.c` records only the base `a`.
- **Denylist**: Python builtins, keywords-as-names (`True`, `False`, `None`), and Ren'Py's API namespaces and common globals (`renpy`, `config`, `store`, `gui`, `build`, `preferences`, `_`, `ui`, `im`, `Character`, `Transform`, ...) are dropped from the index unless the project defines them: walks record them (many, like `time`, `random` or `id`, are common user variable names), and `resolveProjectIndex` discards one only when it would otherwise be unresolved (nms4.13). Underscore-prefixed names are never recorded. The list is a single exported constant so tests and later tuning share it.
- **Python definitions**: a top-level `def f` or `class C` in a python block defines `python-function:f` or `python-class:C`. At that level, a plain `x = …` in a `python:`/`init python:` block is recorded as a `write` (a store assignment), the same as `$ x = …`.
- Calls such as `f()` are `read`s of `f`. Resolution (Section 3) matches them to `python-function`/`python-class` definitions before falling back to variables.

**Errors.** `hasError` is the root's `hasError`. Statements outside ERROR regions are still extracted, so a half-typed line doesn't empty the file's contribution. If parsing or extraction throws, the builder returns an empty contribution with `hasError: true` instead of rejecting.

### 3. Project resolve (`src/lib/tree-sitter/projectIndex.ts`)

```ts
export function resolveProjectIndex(contributions: Map<string, BlockContribution>): ProjectSymbolIndex;
```

A pure, synchronous function. It never parses.

1. **Collect definitions** into `symbols`, grouped by `symbolId`.
2. **Implicit variable definitions.** For each variable name that has `write` references but no `define`/`default` definition, promote the earliest write (ordered by `filePath`, then `start.offset`) to a definition with `defKind: 'implicit'`. That write also stays in the references list. So `$ flag = True` with no `default` still has a definition to navigate to, while `default points = 0` plus later `$ points += 1` stays one definition plus one write.
3. **Resolve references:**
   - Labels: exact qualified-ID match. Callers have already qualified `.x` against their enclosing global label.
   - Images: tag match. A reference resolves to `image:<full name>` when that is defined. Otherwise it resolves to the shortest defined image whose tag (first word) matches; when there are none, it is unresolved. The reference keeps its full name. This approximates Ren'Py's attribute matching closely enough for navigation.
   - Variable `read`s: a `python-function`/`python-class` with that name, then `character:`, then `variable:`.
   - Everything else: exact ID match.
   - Dynamic references (`symbolId: null`) are attached to nothing and are not unresolved.
4. **Unresolved**: resolvable references with no matching symbol, for example a jump to a missing label or a show of an undefined image tag. Reads of names on the denylist never get here, because they are never recorded.
5. **Duplicates**: label and screen IDs with more than one definition.

Output ordering is deterministic (by `filePath`, then offset) so tests and diffs are stable.

**Incremental update** (`src/lib/tree-sitter/projectIndex.ts`):

```ts
export interface ContributionCache { byBlockId: Map<string, BlockContribution> }

export async function updateProjectIndex(
  cache: ContributionCache,
  blocks: { id: string; filePath: string; content: string }[],
): Promise<ProjectSymbolIndex>;
```

It hashes each block (djb2, moved from the worker into a shared `src/lib/contentHash.ts`), rebuilds contributions only for new blocks and blocks whose hash or `filePath` changed, drops blocks that are no longer present, and calls `resolveProjectIndex`. Keeping this logic out of the worker file makes it unit-testable.

### 4. Worker integration (`src/workers/renpyAnalysis.worker.ts`)

- The worker holds one module-level `ContributionCache`.
- After the existing regex phases, it posts progress (`'Indexing symbols'`) and awaits `updateProjectIndex`. The result is attached as `result.symbolIndex`.
- `RenpyAnalysisResult` gains `symbolIndex?: ProjectSymbolIndex` and `indexError?: string`. Both are optional, so `EMPTY_ANALYSIS_RESULT` and every existing consumer are untouched.
- The existing whole-result cache (identical signatures → return the cached result) stays. It already covers position-only changes, and the cached result includes the index.
- The handler becomes `async`. Requests are already tagged with `id`, and the hook ignores stale ids, so overlap behaves as it does today. Real cancellation is `nms4.3`.

### 5. Error handling

| Failure | Behavior |
|---|---|
| Parser/WASM init fails in the worker | Regex result still posts; `symbolIndex` omitted; `indexError` set; one `console.warn` per worker lifetime |
| One block throws during extraction | That block gets an empty contribution with `hasError: true`; the rest of the index builds normally |
| Block has syntax errors | Contribution built from intact statements; `hasError: true` |
| `resolveProjectIndex` throws (bug) | Same as init failure: regex result posts, `indexError` set |

The regex analysis result must be byte-for-byte what it is today in every case.

## Testing

All parser-backed tests go through the real committed WASM, like the existing `treeSitter*.test.ts` suites.

- **`src/test/blockContribution.test.ts`**: one focused test per extraction rule. Each definition kind; jump/call including `expression`; local and dotted label qualification; `call … from`; show/scene/hide image names; `call`/`show`/`hide screen` and `use`; say speakers including narration (no reference); `[var]`, `[var.attr]` and `[var!t]` interpolation; Python writes vs reads, augmented and tuple targets; `def`/`lambda`/comprehension locals not recorded; `store.`/`persistent.` normalization; denylisted names not recorded; top-level `def`/`class` definitions; `context` values for each injection kind; Python reference ranges mapped back to the right `.rpy` line and column, including a CRLF variant; a block with a syntax error still yielding its intact statements; trees disposed even when extraction throws (spy on `disposeParsedBlock`).
- **`src/test/projectIndex.test.ts`** with a fixture project in `src/test/fixtures/symbol-index/` (`script.rpy`, `chapter1.rpy`, `screens.rpy`, `init.rpy`): a cross-file jump and call; a local label reached from a sibling file via `start.sub`; screens defined in one file and called, shown and `use`d from others; a variable `default`ed in `init.rpy`, written in `chapter1.rpy` and interpolated in `script.rpy`; implicit-definition promotion; a missing label in `unresolved`; a duplicate label across two files in `duplicates`; image tag resolution including an unresolved tag; a character defined in `init.rpy` and spoken in `script.rpy`; deterministic ordering.
- **Incremental updates** (`updateProjectIndex`): changing one block rebuilds only that block (spy on `buildBlockContribution`); an unchanged run rebuilds nothing; a removed block's symbols and references disappear; a renamed `filePath` is rebuilt.
- **Worker**: `symbolIndex` survives `structuredClone`; with `updateProjectIndex` mocked to throw, the regex result still posts with `indexError` set and no `symbolIndex`.
- **Regression**: the full existing suite, `tsc --noEmit` and eslint stay green, and existing worker/analysis tests show no change in the regex result.

## Open Questions

- **Denylist contents.** The initial list covers Python builtins and the Ren'Py namespaces above. Real projects may surface more noise in `unresolved`; tuning it is expected and cheap because it is one constant.
- **Image attribute matching.** Tag-based resolution is an approximation of Ren'Py's attribute matching. If nms4.5's navigation shows it is too coarse, refine there.
